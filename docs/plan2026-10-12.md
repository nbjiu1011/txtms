•   역할 변경은 기존 고객사·프로젝트 접근 범위를 자동으로 넓히지 않습니다.
2.3 권한 원칙
•   데이터는 고객사를 최상위 단위로 구분합니다.
•   조회·수정·상태 변경 권한은 역할과 소속 프로젝트를 함께 기준으로 판단합니다. 서버는 활성 계정의 역할과 소속 프로젝트를 확인하여 접근을 허용합니다.
•   프로젝트에 소속된 요청자·검수자·대표 검수자·승인자는 해당 프로젝트의 모든 요청과 하위 콘텐츠를 조회합니다. 조회를 분리해야 하는 업무는 별도 프로젝트로 구성합니다.
•   단, 작성 중 상태의 요청은 작성한 요청자만 조회할 수 있습니다. 요청 취소나 회수로 작성 중으로 돌아간 요청도 같으며, 취소·회수 처리는 이력으로 남깁니다.
•   편집·상태 변경은 요청자·배정 검수자·주담당·프로젝트 승인자·해당 관리자 등 요청별 역할 조건을 함께 만족해야 합니다.
•   고객사 단위 기능은 해당 관리자에게, 승인 메뉴는 승인 단계를 사용하는 프로젝트의 승인자에게만 제공합니다.
•   메뉴 표시 여부와 관계없이 직접 주소 입력, 연동 인터페이스(API), 첨부파일, 다운로드, 검색, 알림에도 같은 권한 조건을 적용합니다. 권한이 없는 요청에 접근하면 접근 차단을 안내합니다.
2.4 관리자와 운영 담당자의 접근
•   고객사 관리자는 소속 고객사의 모든 프로젝트에 접근할 수 있습니다.
•   솔루션 운영 담당자는 고객사 콘텐츠에 자동으로 접근할 수 없으며, 대상 프로젝트 권한과 접근 기간을 별도로 부여받아야 합니다. 모든 조회·수정·내보내기 이력을 남깁니다.
•   관리자 권한은 이후 납품 방식·권한 정책에 따라 달라질 수 있으며, 1차에는 모든 고객사에 같은 기준을 적용합니다.
2.5 로그인과 계정
•   1차에는 이메일과 비밀번호로 로그인하는 자체 로그인을 실제로 구현합니다(계정 저장·인증 포함). 통합 로그인(SSO)은 후속 범위입니다.
항목
규칙
가입
고객사 관리자가 이메일로 초대하면 사용자가 초대 링크를 수락하고 비밀번호를 설정합니다. 초대 링크는 7일간 유효하며, 다시 발급하면 이전 링크는 쓸 수 없습니다. 회사 도메인이 아닌 이메일을 초대하면 막지 않고 초대 전에 경고합니다.
비밀번호
8자 이상이며 영문·숫자·특수문자 중 2종 이상을 포함합니다. 비밀번호 재설정은 이메일로 보낸 링크(1시간 유효)로 진행합니다.
로그인
이메일과 비밀번호로 로그인하며, 실패하면 오류를 안내합니다.
세션
30분 동안 사용하지 않으면 로그인 상태(세션)가 만료됩니다. 로그인 유지를 선택하면 최대 14일간 유지하며, 이때는 30분 만료를 적용하지 않습니다. 로그아웃을 제공합니다.
권한 변경 반영
역할이나 권한이 바뀌면 다음 요청부터 서버에서 새 권한을 적용합니다.
계정 정보 변경
본인은 이름·소속만 변경합니다. 이메일·역할·권한은 고객사 관리자가 변경하며, 이메일을 바꾸면 새 주소로 보낸 확인 링크로 확인한 뒤 반영하고 이력을 남깁니다.

•   역할별 체험 로그인(A-1.2)은 시연·검증용으로 1차에 포함합니다. 실제 계정·인증과 분리하고, 시연에 사용한 데이터는 실제 운영 실적과 구분합니다. 구현 방식은 「기능 정의」 A-1.2에서 회신받습니다.

•   상태는 요청 단위로 적용하며, 요청에 포함된 모든 콘텐츠는 같은 요청 상태를 따릅니다.

•   사용자가 할 수 있는 행동은 역할·프로젝트·현재 요청 상태를 서버에서 확인해 결정합니다.

4.6 텍스트 교정
•   사용자는 텍스트 교정을 선택적으로 실행할 수 있습니다. 교정 실행 여부는 검수 요청이나 검수 완료의 필수 조건이 아닙니다. 교정 실행 기능 자체는 이번 출시의 필수 구현 범위입니다.
•   검출할 표현과 대체할 표현을 정한 규칙 데이터셋으로 교정을 실행합니다. 고객사와 콘텐츠 유형별로 적용 가능한 유효 데이터셋을 사용합니다.
•   다건의 문안을 등록한 요청에는 전체 검사를 제공합니다. 한 번 실행하면 교정 가능한 모든 문안을 검사하고 결과를 문안별 카드로 표시합니다. 검수자도 검수 중에 같은 기능을 사용합니다.
•   문안·변수·연결값을 바꾸면 기존 교정 결과를 ‘최신 내용과 불일치’로 표시합니다.
•   첨부파일이 하나라도 있는 자유입력형은 교정 버튼과 결과 영역을 비활성화하고 전체 검사에서 제외하며, 기존 결과를 검수 근거로 사용하지 않습니다. 첨부파일을 모두 삭제하면 다시 활성화합니다. 자유입력형은 첨부파일 유무와 관계없이 텍스트 교정을 실행할 수 있습니다. 교정 대상은 입력창에 직접 입력한 텍스트로 한정하며, 첨부파일 내부의 텍스트 추출 및 검사는 수행하지 않습니다. 전체 검사 시에도 입력창의 텍스트만 검사 대상으로 포함합니다.(261012 RCS 유형 보류)
•   교정 엔진의 동작 명세와 유형별 시드(초기 샘플·기준 데이터)는 와이어링크가 개발 착수 전에 제공합니다(확인 04).

4.7 작성 가이드와 목업
•   가이드와 체크리스트는 현재 유형의 원칙·권장 표현·점검 항목을 읽기 전용으로 제공합니다.
•   업무 화면을 유지한 채 참고할 수 있으며, 조회나 체크 완료를 다음 단계 전환의 필수 조건으로 삼지 않습니다.
•   일반 작성 가이드에는 별도 변경 내역 탭을 두지 않습니다.
•   목업은 알림톡·문자·RCS의 표시 형태를 미리 확인하는 작성 보조 화면입니다. 글자 수와 바이트 안내, 목업 화면만으로 외부 채널 등록·심사 통과 또는 발송 성공 여부를 확인할 수는 없습니다.(261012 RCS 유형 보류)
4.8 제출과 요청 취소
•   제출 시 유형별 필수값과 연결값을 확인합니다. 텍스트 교정 실행 여부 및 결과는 제출 조건으로 요구하지 않습니다.
•   자유입력형에 첨부파일이 있는 경우, 첨부파일과 파일별 검수 범위를 추가로 확인합니다. (261012 수정)
•   누락이 없으면 서버에 저장한 뒤 배정 대기로 전환합니다.
•   검수자가 배정되기 전(배정 대기)에는 요청자가 요청을 즉시 취소할 수 있습니다. 요청은 작성 중으로 돌아가고 취소 행동을 업무 이력에 기록합니다.
5 검수
제출된 요청에 검수자를 배정하고, 검수를 진행해 완료하기까지의 과정입니다.
5.1 검수자 배정
•   대표 검수자가 배정 대기 요청에 검수자를 1명 이상 배정하고 그중 1명을 주담당 검수자로 지정합니다.
•   검수자가 여러 명이어도 요청 단위 검수 완료와 회수 요청의 승인·거절은 주담당 검수자 1명만 처리합니다.
•   검수 중 상태에서는 사유와 인수인계를 입력한 뒤 담당 검수자 또는 주담당을 변경할 수 있고, 기존 기록은 보존합니다.
•   변경 불가 상태: 확인 요청·승인 대기·검수 완료·승인 완료
5.2 검수 작업과 편집
•   배정 검수자는 요청이 검수 중일 때만 검수 작업과 검수 의견 등록을 할 수 있습니다.
•   요청자: 요청이 작성 중이거나 확인 요청에 응답하는 동안 본인 콘텐츠를 수정
•   담당 검수자: 요청이 검수 중일 때 편집
•   문안별 편집 잠금과 저장 버전 비교로 다른 사용자의 최신 내용을 덮어쓰지 않습니다. 편집 잠금은 30분 동안 입력이 없으면 자동 해제되며, 대표 검수자·고객사 관리자가 강제로 해제할 수 있습니다(이력 기록).
•   파일 수정본은 새 버전으로 올립니다.
내용 판단의 기준
•   텍스트 교정은 표현 검토를 보조합니다.
•   사실관계·고객사 기준·외부 심사 통과 여부는 별도 근거로 확인합니다.
•   교정 제안이 사실이나 고객사 기준과 충돌하면 담당자가 판단합니다.
•   파일 내용과 수정본은 사람이 확인합니다.
5.3 확인 요청
•   검수자는 질문이나 확인할 내용을 대상 콘텐츠와 함께 요청자에게 보냅니다. 요청 전체가 확인 요청으로 전환되고 검수는 일시 중단됩니다.
•   질문·답변과 대상 콘텐츠를 업무 이력에 기록합니다.
•   요청자가 답변하면 요청은 검수 중으로 돌아갑니다. 같은 검수 과정에서 여러 번 반복할 수 있습니다. 요청자가 답변하면서 콘텐츠 문안을 수정하면 검수 차수가 1회 증가합니다.
5.4 회수 요청
검수가 시작된 뒤에는 요청자가 직접 취소할 수 없고, 주담당 검수자에게 회수를 요청합니다.

•   취소·회수는 요청을 작성 중으로 되돌리는 행동이므로 별도의 취소 완료 상태나 보관 원본을 만들지 않고 처리 이력만 보존합니다.
5.5 검수 완료
•   주담당 검수자는 공동 검수 결과와 대상 버전을 최종 확인한 뒤 검수 완료를 처리합니다.
•   승인 단계를 사용하지 않는 고객사는 이 시점에 검수 완료가 최종 완료가 되고, 사용하는 고객사는 승인 대기로 전환됩니다.
6 승인과 재검수
승인 단계를 사용하는 고객사에서 검수 완료 이후 최종 승인까지의 과정입니다.
6.1 승인자와 승인 조건
•   승인 단계를 사용하는 고객사는 프로젝트별로 승인자를 1명 이상 둡니다.
•   승인자는 프로젝트의 모든 승인 대기 요청을 처리하며, 요청별 담당자는 두지 않습니다.
•   해당 요청을 승인할 권한이 있는 승인자 1명이 처리하면 상태를 변경합니다. 승인자 전원의 합의는 요구하지 않습니다.
•   승인할 수 없는 경우: 관리자 권한만 있는 경우, 해당 요청의 요청자·배정 검수자·주담당(승인자 역할이 있어도 해당 요청은 처리 불가)
활성 승인자가 없을 때
•  승인 대기 전환을 차단합니다.
•  고객사 관리자에게 승인자 지정을 요청하고, 요청자와 대표 검수자에게 지연을 알립니다.
•  임시 승인 위임은 두지 않습니다.
•  활성 승인자는 있으나 해당 요청을 처리할 적격 승인자(요청자·배정 검수자·주담당이 아닌 승인자)가 없는 경우에도 같은 절차를 적용합니다.

 
6.2 승인 대기 중 처리
•   콘텐츠 버전·검수자·주담당을 고정합니다. 이 동안 검수자 변경은 할 수 없습니다. 확정 납기·긴급도는 승인자만 변경할 수 있으며 변경 전후 값을 기록합니다.
•   프로젝트 승인자는 대상과 변경 내용을 확인해 승인하거나 수정 요청합니다.
•   수정 요청으로 재검수한 뒤 다시 승인 대기로 전환되면, 승인자는 새 검토 대상 버전을 다시 확인합니다.
6.3 수정 요청과 검수 차수
•   승인자가 수정 요청하면 이유·위치·기대 내용을 기록하고 요청을 검수 중으로 돌려보냅니다. 기존 검수자와 주담당이 수정·재검수·검수 완료를 수행합니다.

메뉴와 콘텐츠 화면을 제품 내부 탭으로 엽니다. 탭 영역의 오른쪽 끝에 있는 추가 버튼으로 사용 권한이 있는 메뉴 또는 콘텐츠를 새 탭으로 열 수 있습니다. 콘텐츠 목록에서도 선택한 콘텐츠를 새 탭으로 열 수 있습니다. 동시에 최대 10개까지 열 수 있습니다.
탭 이동
열린 탭 사이를 이동할 수 있으며 각 탭의 입력 중 내용·스크롤·필터 상태를 유지합니다. 새로고침하거나 다시 로그인하면 탭 목록만 복원합니다.
탭 종료
각 탭을 개별 종료합니다. 저장하지 않은 변경 내용이 있으면 종료 전에 경고합니다.
교정 결과 이동
다른 탭 문안의 교정 결과 카드를 선택하면 해당 탭으로 전환한 뒤 대상 문자열 위치로 이동합니다.

11.2 구성원과 조직 변경
•   구성원 비활성화·역할 해제·프로젝트 제외 또는 사용 중지 전에 진행 업무 영향과 대체자를 확인하고 인수인계를 완료합니다.
•   프로젝트 승인자 구성은 프로젝트 권한으로 관리하며 변경 전후와 실행자를 기록합니다. 이미 완료된 승인 행위의 행위자 이력은 그대로 보존합니다.
•   이력이 연결된 고객사·구성원·프로젝트는 물리 삭제하지 않고 비활성 상태로 보존합니다. 과거 결과·책임 이력·행위와 접근 이력을 유지합니다.
•   고객사 물리 삭제는 이번 출시 범위에 포함하지 않으며, 필요 시 후속으로 협의합니다.
11.3 솔루션 운영 기능
•   솔루션 운영 담당자는 고객사 생성·조회·비활성, 콘텐츠 유형 사용 상태, 고객사 × 콘텐츠 유형별 교정 데이터셋 배정, 초기 설정·시드 데이터를 관리합니다.
•   알림톡·문자·RCS·자유입력 콘텐츠 유형의 사용 상태를 관리하며, 과거 요청을 신규 유형으로 자동 변환하지 않습니다.(261012 RCS 유형 보류)
•   가이드·체크리스트와 교정 데이터셋의 변경 이력을 구분합니다.
11.4 교정 데이터셋
•   고객사별, 콘텐츠 유형별로 유효 데이터셋이 다릅니다.
•   1차에는 유효 데이터셋을 저장하는 구조(데이터 모델), 초기 데이터(시드), 배정 기능을 모두 구현합니다. 솔루션 운영 담당자가 고객사와 콘텐츠 유형별로 배정한 유효 데이터셋(시드)으로 텍스트 교정을 실행합니다.
