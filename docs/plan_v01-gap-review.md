## 1. 클라이언트 의견 반영

### ① 요청 작성 · 요청자 — 첨부가 있는 자유입력형의 제출 검증

| 확인 항목 | 결과 |
|---|---|
| 첨부가 있어도 공통 필수값(제목·유형·희망 납기·목적·대상 고객·배경)을 검증하는가 | 검증함. `validateReq`에 첨부 때문에 검증을 건너뛰는 분기가 없음 |
| 파일별 전체 분량·실제 검수 범위, 첨부 한도, 업로드·검사 완료를 검증하는가 | 검증함 |
| 텍스트를 함께 입력한 경우 변수 유효성을 검증하는가 | 검증함 |
| 교정 버튼·결과 비활성, 전체 검사 제외, 첨부 전체 삭제 시 재활성화 | 동작함 |
| 화면에 "파일과 검수 범위만 확인"으로 읽히는 문구가 있는가 | 없음 |

프로토타입 동작은 클라이언트 의도와 같다. 플로우차트(`plan_v01-flowchart.md` ①)에서 **텍스트 교정(선택)**과 **제출 검증(필수)**을 별도 흐름으로 나눴다.

클라이언트가 직접 정리하기로 한 문구의 제안안:

- 기획서 4.8: "첨부파일이 있는 자유입력형 콘텐츠는 텍스트 교정 대상에서 제외하며, 교정 결과 없이 제출할 수 있습니다. 그 외 필수값은 다른 콘텐츠와 같이 제출 시 검증합니다(공통 필수값, 파일별 전체 분량과 실제 검수 범위, 첨부 개수·용량, 업로드와 파일 검사 완료 여부, 텍스트를 함께 입력한 경우 사용한 변수)."
- 기능명세 B-8.1: "유형별 필수값·연결값 확인. 첨부파일이 있는 자유입력형도 공통 필수값과 첨부 조건(파일별 분량·검수 범위, 첨부 한도, 업로드·검사 완료)을 확인하며 텍스트 교정만 제외. 교정 결과의 불일치는 안내만 하고 제출을 막지 않음."

### ③ 검수 · 배정 검수자 — 담당자 구분과 검수자 변경 흐름

권한 처리는 문서와 맞았다. 검수 작업은 배정 검수자 전원, 요청 단위 검수 완료와 회수 처리는 주담당만, 검수자 변경은 대표 검수자가 `검수 중`에서만 할 수 있다. 다음 부족한 점은 이번에 수정했다.

| 부족했던 점 | 수정 내용 |
|---|---|
| 주담당이 아닌 검수자에게 "검수 완료는 주담당이 처리한다"는 안내가 없음 | 검수 중 화면에 역할별 안내 배너 추가(공동 검수자 / 주담당) |
| 검수자 변경 시 이전 배정이 자유 텍스트 이력으로만 남음 | `assignHist`에 변경 전·후 검수자, 주담당, 사유, 인수인계, 차수를 구조화해 기록. 주담당이 바뀌면 이력에 `주담당 변경: A → B` 줄 추가 |
| 주담당만 바꿀 때 이전 주담당이 알림을 받지 못함 | 알림 대상에 변경 전후 주담당 추가 |
| 내용이 같은 변경도 저장됨 | 바뀐 검수자·주담당이 없으면 저장하지 않음 |
| 해제된 검수자의 편집 잠금이 기록 없이 풀림 | 잠금 해제를 콘텐츠 이력에 기록 |
| 검수 완료 확인 창의 "공동 검수 결과"에 이전 담당자의 의견이 빠짐 | 의견을 남긴 이전 담당자도 `(이전 담당)`으로 표시 |
| 회수 요청 중에 확인 요청을 보낼 수 있어 회수 처리가 막힘 | 회수 요청이 처리될 때까지 확인 요청 차단 |
| 강제 잠금 해제 버튼이 대표 검수자에게만 보임(처리 권한은 고객사 관리자도 있음) | 고객사 관리자에게도 버튼 표시 |
| 회수 거절 이력에 기존 배정이 없음 | 거절 이력에도 기존 배정 기록 |

`verify-plan-v01.cjs`에 검사 6개를 추가했다. 첨부가 있는 자유입력형의 공통 필수값 검증, 변경 사유·인수인계 필수, 동일 변경 거부, 이전 배정 기록, 이전 주담당 알림, 회수 중 확인 요청 차단을 검사한다. 정책·흐름 61개, 첨부·인증 10개 검사가 모두 통과했다.
