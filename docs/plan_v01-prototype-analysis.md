# TX TMS 프로토타입 · plan_v01 분석 및 수정 내역

기준 문서: `docs/plan_v01.md` (1–40절). 기존 `TX_TMS_Project_Plan_v1.0.md`의 협의 표시는 이번 기획의 확정 규칙보다 우선하지 않는다.

실행: `tx-tms-prototype.html`을 브라우저로 연다. `tx-tms-plan-v01.js`를 같은 폴더에 유지한다. XLSX 및 ZIP 라이브러리는 CDN 연결이 필요하다. 기존 데이터의 오염을 피하도록 전용 브라우저 저장 키를 사용한다.

## 기존 프로토타입 분석

기존 화면은 역할별 대시보드, 요청/콘텐츠 편집, 공동 검수, 확인 요청, 회수, 승인, 검색, 관리 메뉴를 이미 포함했다. 하지만 다수 기능이 안내용이거나 이전 협의안에 맞춰 동작했다.

- 배정 전 취소에도 재제출 시 차수를 올렸다. 확인 응답의 문안 수정에는 차수를 올리지 않았다.
- 승인자 존재만 확인하고 요청 참여자를 제외한 적격 승인자 존재를 확인하지 않았다.
- 자동 저장은 화면 표시만 바꾸고 새로고침하면 데이터가 사라졌다.
- 첨부 원본을 저장하지 않았고 다운로드/XLSX/ZIP은 토스트만 표시했다.
- 첨부 제한은 파일당 50MB로 구현했고 요청 전체 개수/합계 검사가 없었다.
- 변수 키에 한글을 허용하고 자료형/값 검증 및 완료 시점 값 고정이 없었다.
- 교정 결과의 신선도는 일부 텍스트만 비교해 연결값과 변수 값 변경을 놓쳤다.
- 로그인·초대 수락·비밀번호·세션은 실제 동작이 없는 화면이었다.
- 업무량에 제목/버튼을 포함하고 기간 계산은 2026년 9월 고정값을 사용했다.
- 운영 담당자가 자기 자신에게 콘텐츠 조회 권한을 부여할 수 있었다.
- 탭은 12개를 권장할 뿐 제한이 없었다. Phase 2 공개범위/오탐/배포 기능이 실행 가능했다.

## 검증

`node verify-plan-v01.cjs`로 45개 정책/워크플로·첨부·인증 검사를 수행했다. 배정 전 취소 재제출, 대표 배정, 확인 요청의 설명/문안 수정 응답, 회수 승인 후 재제출, 승인 미사용 완료/후속 요청을 연결된 흐름으로 검증한다. 초안 접근, 주담당 권한, 참여자 승인 제외, 잠금 만료, 변수 자료형/값 보존, 탭 한도, 링크 재발급, KST 경계도 검사한다.

실제 브라우저에서 로그인, 요청자 대시보드, 새 요청 편집, 관리자 사용자·권한 화면을 확인했고 페이지 오류가 없었다. XLSX·ZIP·보완 스크립트가 실제로 로드됨도 확인했다. 추가 검증 결과와 화면은 `plan_v01-request-preview.png` 및 에이전트 작업 결과를 참조한다.

## 전체 정합성 추가 검증 (2026-10-07)

외부 도메인 초대는 주소별 경고 확인 후 재실행해야 생성된다. 주소가 바뀌면 확인을 다시 받는다. 승인 적격성은 요청자·배정 검수자·주담당을 각각 제외하고 활성 계정만 인정한다.

첨부 화면에 정상/검사 실패/위험 파일 시연 결과 선택과 업로드 중·파일 검사 중·업로드 완료·검사 실패·위험 차단 상태를 추가했다. 실패와 위험 결과는 첨부 등록 전에 차단한다. 업로드 중 제출·완료 등 충돌 행동도 차단한다. 이 검사는 실제 악성파일 검사를 대신하지 않는다.

`node verify-plan-v01.cjs`의 65개 검사가 통과했다. 동일 범위 복수 후보, 긴 표현 우선, 권장 표현 재검출 제외, 길이가 바뀐 뒤 후속 교정 위치, 적용 및 역순 복원, 외부 도메인 확인, 승인 참여자 제외, 수정 요청의 차수/배정 유지, 적격 승인자 1명의 최종 승인과 검사 실패·위험 차단을 추가 검증했다. 이 실행은 DOM을 단순화한 Node VM 검사이며 실제 브라우저 전체 검증을 의미하지 않는다.

### 서버 연동 경계

HTML 프로토타입을 수정하는 작업과 운영 서비스 구축은 별개다. 현재 파일에는 백엔드/API 서버가 없다. 따라서 서버 인증·세션, 권한 있는 파일 저장/다운로드, 악성파일 검사, 실제 메일, 브라우저가 닫혀 있어도 실행되는 재통지, 여러 기기 간 잠금·충돌 제어는 이 프로토타입만으로 완료되지 않는다. 이 항목은 화면상 구현 완료로 오인하지 않도록 시연과 서버 연동을 구분했다.


추가 확인: 파일 업로드 중 제출/첨부 변경 차단, 파일이 있는 자유입력형의 교정 결과 비활성화와 전체 제거 후 재활성화, 테마 화면·행동의 Phase 2 분리를 검증했다. 데이터셋 등록은 단일 권장 표현과 복수 권장 표현 배열을 모두 지원한다. 비활성 계정은 비밀번호 재설정으로 다시 활성화되지 않는다.

이번 실행의 Chrome 화면 확인은 샌드박스 GPU 프로세스 오류로 완료하지 못했다. 샌드박스 밖 재시도에서도 DOM 출력이 없어 브라우저 검증 성공으로 집계하지 않았다. 위 검증 수치는 Node VM 및 파일/인증 함수 검사 결과다.
